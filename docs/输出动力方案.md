# 「输出动力」功能方案（通用构件）

## 需求

通用构件：背罐接受红石信号时，以 16 转速 / 32 应力逆时针旋转，每秒消耗 1 单位气体。

## API 调研结论

| 事实 | 依据 |
|---|---|
| 已放置的背罐是 `KineticBlockEntity` | `BacktankBlockEntity extends KineticBlockEntity` |
| 它的旋转轴是**竖直 Y 轴** | `BacktankBlock.getRotationAxis() → Axis.Y` |
| 接入面由 `hasShaftTowards` 决定 | 同上 |
| 成为动力源只需覆盖两个方法 | `getGeneratedSpeed()`（返回 0 即为耗能端）、`calculateAddedStressCapacity()` |
| 参考实现 | `CreativeMotorBlockEntity` 只重写 `getGeneratedSpeed()` |
| Create 每 tick 会把气量钳到上限 | `airLevel = min(max, airLevel + increment)` |

## 实现方案

全部走已跑通的 Mixin 通道，注入 `BacktankBlockEntity`：

### 1. `getGeneratedSpeed()`

```
若 已装通用构件 且 红石信号 > 0 且 气量 > 0
    → 返回 -16（逆时针，符号待游戏内确认）
否则 → 返回 0
```

注入方式：`@Inject(method = "getGeneratedSpeed", at = @At("RETURN"), cancellable = true, remap = false)`。

### 2. `calculateAddedStressCapacity()`

```
若 正在输出动力 → 返回 32
否则 → 保持原值
```

⚠️ 单位待确认：Create 里该方法的返回值是 **SU per RPM**，不是总 SU。若"32 应力"指总量，则应为 `32 / 16 = 2.0`。

### 3. 气体消耗

在 `tick` 的 RETURN 处：

```
若 正在输出动力
    airLevel = min(airLevel, airBefore) - 0.05      // 每秒 1 单位 = 每 tick 0.05
```

**关键**：这里必须用 `airBefore` 覆盖 Create 当 tick 充进去的气，否则背罐会**自己转自己充**，变成永动机。

### 4. 红石信号

`level.hasNeighborSignal(worldPosition)`，每 tick 检测即可（背罐不需要响应红石变化事件）。

## 必须处理的坑

| 风险 | 处理 |
|---|---|
| **永动机**：旋转导致自充气 | 生成时把气量回退到 tick 前的值再扣 | 
| 气量耗尽后仍输出动力 | `getGeneratedSpeed` 里检查气量，耗尽返回 0 |
| 与充气逻辑冲突 | 生成时不进入充气分支（靠上面的回退实现） |
| 转速方向反了 | 符号（±16）游戏内实测后调整 |
| 应力单位误解 | 先按 SU/RPM 实现，实测后调 |

## 待确认

1. **32 应力**是总量还是 SU/RPM？（总量 → 填 2.0；SU/RPM → 填 32）
2. **逆时针**的观察基准：从轴上方看，还是从侧面看？（决定正负号）
3. 输出动力时是否仍然保留"被外部转动可以充气"的能力？（建议：是，两者互不干扰——只有气量>0 且通电时才会自己转）

## 实施顺序

1. 加 `getGeneratedSpeed` 注入，先只做"红石通电就转"（不扣气），确认能带动传动网络
2. 加气量消耗与永动机回退
3. 加应力容量
4. 调整方向与单位
