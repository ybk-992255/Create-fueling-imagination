## 一、Create —— 可以直接用的基础设施

### 1. `SmartBlockEntity`（强烈建议采纳）

`foundation/blockEntity/SmartBlockEntity.java`

我们的方块实体都是裸 `BlockEntity`，每个都要自己写 `setChanged()` + `sendBlockUpdated` + 手动同步。Create 的基类直接送这些能力：

```java
public abstract void addBehaviours(List<BlockEntityBehaviour> behaviours);   // 注册"行为"
public void tick();            // 每 tick
public void lazyTick();        // 每 20 tick（省性能）
protected void write(CompoundTag tag, boolean clientPacket);   // 一个方法写两种包
protected void read(CompoundTag tag, boolean clientPacket);
public final CompoundTag writeClient(CompoundTag tag);         // 客户端全量同步
public final void readClient(CompoundTag tag);
public <T extends BlockEntityBehaviour> T getBehaviour(BehaviourType<T> type);
public void forEachBehaviour(Consumer<BlockEntityBehaviour> action);
```

**项目现状对比**：`ProjectorBlockEntity` 每次改数据都手写 `setChanged()` + `sync()`；换成 `SmartBlockEntity` 后 `sendData()` 一句搞定，还白拿 `lazyTick`。

**注意**：`SmartBlockEntity` 要求方块实现 `IBlockEntity` 相关接口，且它依赖 Create 的 `BlockEntityBehaviour` 体系，改造时要把 `newBlockEntity` 和方块类一起换。

### 2. 行为系统 `foundation/blockEntity/behaviour/`

| 类 | 能做什么 |
|---|---|
| `BlockEntityBehaviour` | 模块化的方块实体子逻辑，挂在 SmartBlockEntity 上 |
| `ValueSettingsBehaviour` | **右键拖动/滚轮改数值**，自带数值显示和网络同步 —— 我们的四个滑块可以换成这个，就不用自己写 GUI |
| `ValueBoxTransform` | 3D 空间里的可交互区域（在方块上点某个面来调节） |
| `IHaveGoggleInformation` | 戴工程师护目镜时显示信息面板（`api/equipment/goggles`） |

**对我们的价值**：`ValueSettingsBehaviour` 是"不打开界面就能调参数"的现成方案。放映机的色相/距离/大小，未来可以做成在方块侧面滚动滚轮调节，比 GUI 更符合 Create 的调性。

### 3. 包裹系统（已踩过坑）

`content/logistics/box/PackageItem.java`、`PackageStyles.java`

- `PackageStyles.STYLES` 是「样式 → 物品」**反查表**，自定义包裹**必须用自己的样式**，否则会劫持所有库存包裹（废件箱那个恶性 bug 的根因）
- `PackageItem.containing(List<ItemStack>)` 造一个标准包裹只用来偷 NBT
- `PackageItem.getContents(stack)` 取 `ItemStackHandler`

## 二、GeckoLib —— 模型动画

`com.geckolib` 下：`animatable/`、`animation/`、`cache/`、`loading/`、`model/`、`network/`、`object/`、`renderer/`

关键类：

| 类 | 用途 |
|---|---|
| `animatable/GeoItem` | 物品接口，让物品能播动画 |
| `animatable/instance/AnimatableInstanceCache` | 动画状态缓存 |
| `renderer/GeoItemRenderer` | 物品动画渲染器 |
| `renderer/GeoBlockRenderer` | **方块实体动画渲染器** |
| `model/GeoModel`、`cache/model/GeoBone` | 模型与骨骼 |

`GeoItem` 里值得注意的：

```java
default boolean isPerspectiveAware();            // 按第一/第三人称区分
default AnimatableInstanceCache animatableCacheOverride();   // 视角相关缓存
ItemDisplayContext getCurrentContext();
```

**对我们的价值**：
- `动力集成工具` 的模型动画当初用 BEWLR 三组动画做失败了（紫黑块），GeckoLib 的 `GeoItem + GeoItemRenderer` 是成熟方案，改成 Geo 模型 + `.animation.json` 就能播
- `放映机` 如果要做镜头转动、光柱动画，用 `GeoBlockRenderer`

**代价**：要引入 GeckoLib 作为前置（玩家得装），且模型要从 Blockbench 导出成 geo 格式（用 GeckoLib 的 Blockbench 插件）。

## 四、下一步建议

按性价比排序：

1. **把 `ProjectorBlockEntity` / `PoweredArtisanTableBlockEntity` 改成 `SmartBlockEntity`**
   省掉我们手写的同步代码，白拿 `lazyTick`。风险中等（要连方块类一起改），收益大。

2. **给放映机加 `ValueSettingsBehaviour`**
   在方块上滚轮调节，不用开 GUI。适合"经常要微调"的参数。

3. **GeckoLib 做动力集成工具动画**
   但要先确认玩家是否愿意多装一个前置模组。

4. **Iron's Artifice 的能力体系**——等有具体需求再深入。
