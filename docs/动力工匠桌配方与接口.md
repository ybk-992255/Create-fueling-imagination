# 动力工匠桌：配方与模式接口

## 当前功能

- 有效转速至少 32 RPM、应力网络未过载时才能打开界面。最低转速下占用 512 SU。
- 顶部拨杆在黑色滑槽内左右拖动换挡，松开回弹。模式名称在白色框内靠左显示。
- 制造：放入九宫格材料，下拉右侧拉杆后松开，按拉杆时选中的配方持续批量制造，直到材料不足以再次匹配该配方。每 tick 最多执行 4 次；再次下拉可以停止。成品先进入右侧成品槽，满后进入附近操作者背包，剩余部分掉落在工作台旁。
- 改装：显示中心主物品槽和八个周边槽。暂未提供改装规则；仅在放入主物品后显示槽位说明。
- 维修：只接受带损坏标记的方块（见下一节）。顺时针转动左侧曲柄至少四分之一圈并松开，进入拆解；点击脏污零件，在右侧放大图中按住鼠标，用海绵来回擦拭；全部清洁后再转曲柄重组，清除损坏标记，方块恢复为可放置物品。
- 维修不消耗材料、经验或海绵（海绵为界面工具），也不改动物品的其他 NBT。原版有耐久度的工具、武器、盔甲不再被接受，旧的耐久维修处理器已移除。
- 有合成表的方块按配方展示零件；没有合成表的方块（创造方块、只能石切的方块）显示一个整体部件进行清洁。展示零件不可取走。
- 成功重组不产出任何副产物。损坏组件（`fuelingimagination:damaged_component`）物品仍保留注册并在创造分类中可见，获取方式待定。
- 维修过程中主物品锁定。取消会保留原耐久并解锁；关闭界面、断电或重新加载存档会保留维修进度。
- 切换模式前需清空桌上及鼠标持有的物品。拆除工作台会掉落真实库存，展示零件不会掉落。

## 自动接入的配方与批量规则

- 自动读取当前配方管理器中产物命名空间为 `create` 的原版工作台配方，包括有序、无序和兼容的特殊工作台配方。按产物 ID 判断，不是按配方文件名判断。
- 自动读取产物为 `minecraft` 且属于红石合成类别的配方，并补充红石粉、红石块、信号组件、活塞、漏斗、发射器、投掷器、铁轨/矿车、按钮、压力板、门、活板门、栅栏门等。
- 接入的是工作台配方，不包括机械动力的搅拌、冲压、切削、序列组装或机械合成专属配方。接入不会删除原有的工作台配方；先前红石火把的专属覆盖保持不变。
- 预览和实际合成共用同一套匹配逻辑。数据包修改配方后会自动使用当前加载版本。
- 一个批次只重复最初选中的配方；材料不足后立即停止，不会把剩余材料自动改用另一份配方。
- 批量期间锁定输入槽，成品可以取出；仍需满足原有转速和应力条件。断电暂停、恢复动力继续。操作者退出、死亡、切换维度或配方重新加载后停止；存档重载后保留材料和成品，重新拉杆启动。
- 所有占用的材料槽在每次制造时独立进行材料保留判定，默认概率 10%。例如九个红石粉会各自判定一次。保留材料后，不会同时产生它的空桶等合成返还物。

## TOML 配置

Forge 首次加载存档时会生成 `serverconfig/fuelingimagination-server.toml`：单人存档位于 `.minecraft/saves/<存档名>/serverconfig/`，专用服务器位于 `<世界目录>/serverconfig/`。

```toml
[artisanCrafting]
materialRetentionChance = 0.1
maxCraftsPerBatch = 4096
```

`materialRetentionChance` 范围为 0–1：0 为正常消耗，0.1 为 10% 保留，1 为总是保留。每批次启动时读取配置；此设置独立于 JSON 配方，已有 JSON 不需要修改。
`maxCraftsPerBatch` 是每次拉杆的保护上限，默认 4096 次，防止 100% 保留或可循环使用的材料导致无限合成。通常会先因材料不足停止，未用完的材料仍留在桌上。
模板位于本项目 `docs/config/fuelingimagination-server.toml`。可将模板放入游戏的 `defaultconfigs/`，供新存档使用。

## 添加制造配方

配方类型为 `fuelingimagination:artisan_crafting`，使用原版有序配方的 `pattern`、`key`、`result` 格式。
支持 1×1 到 3×3、平移匹配、水平镜像、物品标签、合成容器返还。拉杆触发批量合成；自定义 JSON 配方优先于自动接入的工作台配方。

把 JSON 放入数据包的 `data/<命名空间>/recipes/<名称>.json`。例如：

```json
{
  "type": "fuelingimagination:artisan_crafting",
  "pattern": [
    "R",
    "S"
  ],
  "key": {
    "R": { "item": "minecraft:redstone" },
    "S": { "item": "minecraft:stick" }
  },
  "result": { "item": "minecraft:redstone_torch", "count": 1 }
}
```

这类配方只由工匠桌读取。若同一产物还有原版工作台配方，需要另外覆盖相应配方 ID；注册工匠桌配方不会自动删除其他配方。

本轮红石火把示例直接位于 `data/minecraft/recipes/redstone_torch.json`，覆盖原版同名配方，因此红石火把改为只能使用此工匠桌配方制造。红石在上、木棍在下。

数据包根目录的 `pack.mcmeta`（Minecraft 1.20.1）：

```json
{
  "pack": {
    "pack_format": 15,
    "description": "动力工匠桌自定义配方"
  }
}
```

将数据包放入存档的 `datapacks` 目录，使用 `/reload` 重新载入。客户端通过原版配方同步获得预览数据。

## 模式扩展

服务端入口：`ArtisanModeHandler`，通过 `ArtisanModeHandlers.register(mode, handler)` 注册。请在 common setup 的 `enqueueWork` 中注册。

| 接口 | 用途 |
| --- | --- |
| `onSelected` / `onDeselected` | 用户切换模式时初始化或收尾 |
| `tickPowered` | 有足够动力时执行，仅服务端 |
| `handleAction(table, player, action, detail)` | 处理曲柄、拉杆确认、拆解、清洁、组装、取消 |
| `describeMainItem(stack, level)` | 生成主物品的改装槽位说明；客户端只在主物品非空时调用 |

`ArtisanAction` 定义 `CRANK`、`CONFIRM`、`DISASSEMBLE`、`CLEAN`、`ASSEMBLE`、`CANCEL`。菜单已校验距离、动力和操作编号，真实物品变动应始终在服务端 handler 中执行。清洁操作的 `detail` 为零件索引 0–8。

`ArtisanProcessStage` 预留改装开槽、等待确认，以及维修拆解、清洁、等待重组阶段。
调用 `table.setProcessState(stage, openedCount)` 可以锁定主物品，并按上→右上→右→右下→下→左下→左→左上的顺序开放 0–8 个周边槽。通过 `table.resetProcess()` 结束流程并解锁。

真实库存索引：

| 索引 | 内容 |
| --- | --- |
| 0–8 | 制造九宫格，逐行排列 |
| 9 | 已完成的制造成品 |
| 10 | 改装或维修主物品，只放一个 |
| 11–18 | 顺时针排列的八个改装组件槽 |

维修展示零件使用独立容器，始终禁止放入、取出和快捷移动。服务器保存物品、模式、流程阶段、脏污与清洁进度；菜单同步槽位和流程数据。

改装 handler 需要在开始前确认主物品有有效改装方案，在确认时校验并消耗组件，再写回升级后的主物品。结束前应处理剩余组件，避免关闭槽位后遗留不可见物品。

当前已实现制造 JSON 配方。后续改装可以新增自己的 `RecipeType` / `RecipeSerializer` 并由 handler 查询；维修规则也可以通过替换 `ArtisanWorkMode.REPAIR` 的 handler 扩展。默认维修规则目前在 `VanillaRepairHandler` 中定义。

## 源码入口

- `client/PoweredArtisanTableScreen.java`：素材区域、布局、拨杆、曲柄、海绵交互。
- `menu/ArtisanMenuLayout.java`：客户端与服务端共用的槽位位置。
- `menu/PoweredArtisanTableMenu.java`：同步、操作校验、槽位访问与快捷移动。
- `block/entity/PoweredArtisanTableBlockEntity.java`：真实库存、流程和存档数据。
- `content/artisan/ArtisanCraftingHandler.java`：批次调度、逐格保留判定、成品和返还物处理。
- `content/artisan/VanillaRepairHandler.java`：原版耐久物品的维修流程。
- `recipe/ArtisanCraftingRecipe.java`、`registry/ModRecipes.java`：JSON 配方解析、匹配、网络同步与注册。

API 结构参考 [Forge 自定义配方文档](https://docs.minecraftforge.net/en/1.19.x/resources/server/recipes/custom/)，实际方法签名以本项目 Forge 1.20.1 依赖为准。

- `recipe/ArtisanRecipeLookup.java`、`ArtisanRecipePolicy.java`：自定义配方优先、Create / 红石工作台配方接入。
- `config/ArtisanConfig.java`：独立的服务端 TOML 配置。
